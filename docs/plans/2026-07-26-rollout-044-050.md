```bash

```

Smoke de schema antes do restart:

- bucket `chat-media` privado;
- tabelas `external_operations`, `departments`, `department_memberships`, `ai_agents`, `transcription_jobs`, `channels`;
- RPCs de claim/finalize/retry com grants mínimos;
- uma configuração default por conta e ausência de ambiguidades no estado atual;
- usuário QA temporário com membership no departamento padrão.

Promote e restart, somente após schema verde:

```bash
python3 scripts/promote-wacrm-production.py
systemctl --user restart wacrm.service
systemctl --user restart wacrm-worker.service
```

O worker de transcrição é um gate separado: instalar/iniciar somente após unit file, owner e limites de CPU/memória aprovados.

## Rollback

### Código

```bash
python3 scripts/rollback-wacrm-production.py
systemctl --user restart wacrm.service
systemctl --user restart wacrm-worker.service
```

O script troca a build atual pela anterior e não reinicia sozinho.

### Banco

As migrations são predominantemente aditivas. Em incidente:

1. interromper novos efeitos externos;
2. reverter código para a build anterior;
3. manter colunas/tabelas aditivas se o código antigo continuar saudável;
4. não executar `DROP` automático;
5. restaurar dump/compensar schema somente com aprovação explícita e análise do dado criado após o rollout.

## Gate de comunicação externa

O E2E de envio outbound continua bloqueado até Anderson indicar um número de teste e autorizar a mensagem exata. Health, webhook, inbound/reconciliação e persistência podem ser certificados sem comunicação externa.
